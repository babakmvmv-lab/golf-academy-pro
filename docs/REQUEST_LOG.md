# وضعیت درخواست‌ها — جلوگیری از اجرای تکراری

این فایل چک‌پوینت دائمی کارهاست؛ تکرار پیام، دستور ساخت دوباره نیست.

## پروتکل پیش از اجرای هر درخواست

1. `git fetch origin main` — نسخهٔ زنده مرجع است.
2. متن کامل پیام را در یک فایل موقت ذخیره و اجرا کنید: `python3 tools/request_fingerprint.py <فایل>`
   - خروجی `duplicate` → اجرا ممنوع؛ فقط وضعیت ردیف ثبت‌شده را گزارش کنید (مگر درخواست صریح دوباره از مالک).
   - خروجی `new` → پیام تکراری نیست؛ فقط دلتای جدید را اجرا کنید و بخش‌های مشترکِ قبلاً انجام‌شده را تکرار نکنید.
3. پس از پایان کار، ردیف جدید با اثر انگشت پیام، وضعیت و commit مرجع به جدول زیر اضافه شود.

**تعریف تکرار:** فقط وقتی «کل پیام» عیناً یکسان باشد (پس از نرمال‌سازی حداقلی: فاصله‌ها، NFC، ی/ک عربی-فارسی) — احتمالاً از کش آمده یا دوبار ارسال شده. حتی یک کلمه تفاوت = درخواست جدید یا الحاقیه. جزئیات کامل در `AGENTS.md`.
